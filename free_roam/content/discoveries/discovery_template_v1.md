# DISCOVERY Authoring Template v1

**Status:** TEMPLATE ONLY · does not assert the player has found an encounter.

## Input: player-observed interruption

- **What did Arthur actually see or hear?** Player's own description; UNKNOWN when unclear.
- **Known area and chapter:** only if reported/canonically confirmed; spoiler budget T0/T1 by default.
- **Original context to preserve:** optional PROJECT / OUTING / Mission (with exact return target).
- **Potential one-time risk:** source-backed specific action/choice, or UNKNOWN—not a blanket "missable!" alarm.

## Response order

1. Acknowledge the actual discovery, not an unrelated preplanned collectible.
2. Give **one safe next interaction or observation** and say what the on-screen feedback would look like.
3. If needed, give a short, specific **before-you-act warning** backed by sources.
4. Let the player choose: investigate, learn the relevant Atlas mechanic or return to the outing.
5. After a reported result, hand facts to GameGuide; only canonical evidence updates actual game state.

## Research and correctness

- Classify named Stranger, random chance encounter, inspectable Point of Interest, item, animal and hostile gang event under the **correct** Atlas family, not all as "Stranger mission".
- Keep surprises intact. Do not produce a map of future unique events unless player explicitly requests spoilers.
- Label rumor, guide inference and observed facts separately; no invented occurrence, item or Honor consequence.
- Text fallback and return target are mandatory. Client visual state is not permanent.

**Acceptance:** supports natural player curiosity, retains source context, avoids spoilage and false urgency, yields no false progress records.
